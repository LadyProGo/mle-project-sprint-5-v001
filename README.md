# Uplift-моделирование для Яндекс Еды

Цель проекта - построить модель для оценки индивидуального эффекта маркетингового воздействия и определить клиентов, для которых промо-коммуникация с наибольшей вероятностью даст дополнительный положительный отклик.

## Описание данных

Датасет содержит данные о 64000 клиентах, участвовавших в маркетинговом эксперименте. Датасет содержит следующие столбцы:

- `recency` - количество месяцев с момента последней покупки;
- `history_segment` - категория расходов клиента за последний год;
- `history` - сумма, потраченная клиентом за последний год;
- `mens` - индикатор покупки товаров для мужчин;
- `womens` - индикатор покупки товаров для женщин;
- `zip_code`- классификация почтового индекса клиента: город, пригород или сельская местность;
- `newbie` - индикатор нового клиента;
- `channel` - канал, через который клиент совершал покупки;
- `treatment` - индикатор маркетингового воздействия;
- `target` - целевая переменная.

## Основные этапы проекта

В рамках проекта были выполнены:

1. Загрузка и первичная проверка данных.
2. Исследовательский анализ данных.

6. Разделение данных на обучающую и тестовую выборки.
7. Обучение и сравнение трёх uplift-подходов:
   - S-learner;
   - T-learner;
   - X-learner.
8. Выбор модели по uplift-метрикам.
9. Подбор гиперпараметров T-learner с помощью Optuna.
10. Дополнительный эксперимент с LightGBM.
11. Финальное обучение выбранной модели.

13. Реализация класса для inference.

15. Проверка корректности модели после повторной загрузки.
16. Регистрация финальной модели в MLflow Model Registry.

## Результаты моделирования

В качестве основной бизнес-метрики использовался `Uplift@30%`, так как задача заключается в выборе верхней части клиентской базы с максимальным ожидаемым дополнительным эффектом маркетингового воздействия.

В первой части проекта были обучены и сравнены S-learner, T-learner и X-learner.

На тестовой выборке T-learner с Random Forest показал:

- `Uplift AUC = 0.028`
- `Qini AUC = 0.063`
- `Uplift@30% = 0.055`

В рамках дополнительной оптимизации T-learner с Random Forest все варианты сравнивались на одной и той же валидационной выборке:

- контрольный запуск исходной конфигурации Random Forest: `Uplift@30% = 0.050`;
- лучшая конфигурация, найденная Optuna: `Uplift@30% = 0.050`;
- дополнительный эксперимент с T-learner на LightGBM: `Uplift@30% = 0.031`.

Таким образом, подбор гиперпараметров с помощью Optuna не улучшил качество относительно контрольной конфигурации на валидации, а LightGBM показал более низкий результат. Поэтому в качестве финальной модели была сохранена исходная конфигурация T-learner с Random Forest, которая на тестовой выборке показала `Uplift@30% = 0.055`.

На тестовой выборке финальная модель сохранила результат:

- `Uplift AUC = 0.028`
- `Qini AUC = 0.063`
- `Uplift@30% = 0.055`

Анализ uplift по перцентилям показал, что наибольший положительный uplift сосредоточен среди верхних 30% клиентов. Это позволяет использовать модель для приоритизации клиентов, для которых маркетинговое воздействие имеет наибольший ожидаемый дополнительный эффект.

## Загрузка переменных окружения MLflow

Для подключения к PostgreSQL и Yandex Object Storage используются переменные окружения из файла `.env`. Так как значения переменных могут содержать специальные shell-символы, вместо прямого выполнения:

```bash
source .env
```

используется безопасная загрузка через `python-dotenv`:

```bash
eval "$(python - <<'PY'
from dotenv import dotenv_values
import shlex

config = dotenv_values(".env")

for key, value in config.items():
    if value is not None:
        print(f"export {key}={shlex.quote(value)}")
PY
)"
```

Endpoint Yandex Object Storage задаётся отдельно:

```bash
export MLFLOW_S3_ENDPOINT_URL="https://storage.yandexcloud.net"
```

После загрузки переменных окружения MLflow-сервер запускается командой:

```bash
./run_mlflow_server.sh
```

MLflow UI доступен локально по адресу:

```text
http://127.0.0.1:5000
```

Он выполняет:

- получение uplift-предсказаний;
- обработку отсутствующих обязательных признаков;
- обработку пропущенных значений;
- обработку пустого DataFrame.

Для интеграции inference с MLflow используется wrapper на основе:

```text
mlflow.pyfunc.PythonModel
```
